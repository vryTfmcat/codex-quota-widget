# Codex Quota Widget

Windows 桌面 Codex 额度悬浮窗：查看 5 小时和每周剩余额度、重置倒计时、Tibo 公告与本地使用统计。

这是独立自用工具，不是 OpenAI 官方应用。界面为简体中文，使用 Windows 本机时区。此版本不包含 WorkBuddy 或机场流量模块，也不会读取这些软件的账户数据或配置。

## 功能

- 常驻置顶的精简状态栏，单击展开/收起，按住拖动移动。
- 顶部手动刷新；额度与公告每 10 分钟自动更新。
- 可独立折叠的额度/时间线、实际使用统计、Tibo 公告、声音设置。
- 左侧竖向阶梯图与右侧窗口卡片共用线性时间轴，100% 在左、0% 在右，时间向下；保留最近 5 小时历史，随当前时间滚动。
- 绿虚线与窗口卡片按最新剩余额度重算；蓝线表示真实采样。
- 5h 剩余 100% 时显示“尚未开始使用”，隐藏倒计时并暂停未来窗口预测；检测到消耗后按接口时间恢复。
- 自动识别 Tibo 已安排公告与观察预告的截止上限，绘制黄线并计算截止前的窗口容量；公告时间修订后自动更新。
- 剩余额度达到 20%、10%、0% 时提醒；窗口到期提醒并重新读取；新公告提醒。
- 固定播放系统自带 `Alarm02.wav` 一次，保留音量、试听与静音。
- SQLite 本地采样，区间消耗柱状图与 24 小时已观测消耗汇总。
- 可选 Obsidian Markdown 总览与按月明细导出。

## 运行要求

- Windows 10/11，Python 3.10 或更新版本，包含 Tkinter。
- 已安装并登录 Codex CLI，或者可发现本机 Codex 应用自带的 CLI。
- 能连接 Codex 服务和公告站点。

仅使用 Python 标准库，没有第三方 Python 依赖。不需要提供 API Key，也不会发起模型推理请求。

## 启动

在源码目录运行：

```powershell
python usage_widget.py
```

也可双击 `launch.cmd`。有 `pythonw.exe` 时以无控制台模式运行。关闭右上角 `×` 会退出程序并停止采样和提醒；电脑睡眠期间不能采样或响铃。

“登录自启开关”仅修改当前 Windows 用户的 `Run\CodexQuotaWidgetPortable` 启动项。默认不开启。再次点击可关闭。

## 数据与隐私

默认运行数据在 `%LOCALAPPDATA%\CodexQuotaWidgetPortable\`，与源码分开：

| 文件 | 用途 |
| --- | --- |
| `widget-state.json` | 位置、折叠状态、声音设置、最近读数与提醒去重 |
| `widget-status.json` | 最近成功读取、脱敏错误、采样/导出状态 |
| `data/usage-history.sqlite3` | 成功采样及脱敏错误类别 |
| `history-export.local.json` | 可选的本机 Markdown 导出配置 |

可在启动前设置 `CODEX_QUOTA_DATA_DIR` 更改数据目录。不要提交自己的数据或本机配置。

额度通过短时启动本机 `codex app-server` 调用 `account/rateLimits/read` 获取。认证由 Codex 管理；工具不直接读取 `auth.json`、浏览器 Cookie、对话内容或任务正文。

统计反映整个账号的额度变化，同账号在其他设备上的使用也会计入。它不能作为单机、单任务或模型的消耗归因。

不要用 Word 打开 SQLite 数据库文件；独占打开会导致采样无法写入。查看统计可用应用界面或可选的 Markdown 导出。

## 计算口径

5h 与每周剩余比例来自服务端，缺失值不当作 0%。下一重置时间来自接口，不简单设置成“现在加 5 小时”。

窗口卡片使用一个独立的容量假设：完整 5h 窗口约能使用周总额度的 **16%**。这是可替换的经验参数，不是官方配额规则，也不是任务速度预测。

```powershell
$env:CODEX_QUOTA_WEEKLY_PER_WINDOW = '16'
python usage_widget.py
```

当前窗口可再使用的周额度约为“参数 × 当前 5h 剩余比例”；随后每个完整窗口最多再使用该参数。最后一张卡片表示最早具备足够容量的窗口，具体几点用完取决于速度。

预测从最新的周剩余与当前 5h 剩余开始计算，每次成功读取都会更新，因此换到新窗口也会重算台阶。历史实际读数保留；不继续沿用本周首次采样时的预测。

“尚未开始使用”是按 5h `usedPercent=0` 的界面规则，不证明后端一定未启动计时。工具仍每 10 分钟读取一次；接口百分比可能取整或延迟，检测到消耗的时刻不等于首次实际使用时刻。恢复倒计时使用接口 `resetsAt`，不从检测时刻另加 5 小时；待使用状态不会按缓存的 5h 时间响铃。

Tibo 优先读取 `scheduled.scheduled_for`，无有效安排时回退到 `watch.expires_at`。黄线是第三方站点解析的时间上限，可能提前，并非承诺的执行时刻；预计时间已过则等待新消息，不自行重置账户读数。刚好在截止点开放的新窗口不计入截止前容量。

统计为相邻成功读数的下降量，单位是周总额度的百分点。自动间隔通常 10 分钟，手动刷新可能更短；超过 15 分钟的长间隔用橙柱表示，不虚构中间点。跨重置、额度反增或缺失字段的区间不计为普通消耗。图表只连接连续且可比较的读数。

## 刷新与故障

- 每次额度读取失败最多尝试 3 次；仍失败则保留旧值，可手动刷新或等下次自动更新。
- 超过 20 分钟没有成功读数标记旧数据。
- 登录失效时，先检查 Codex 的账号登录，再刷新。
- 数据文件被其他程序占用时，关闭占用后刷新；不要修改数据库结构。

## 可选 Markdown 导出

默认关闭，不会自动寻找或扫描你的 Obsidian 库。

1. 将 `history-export.example.json` 复制到运行数据目录，重命名为 `history-export.local.json`。
2. 填写你本机 Vault 路径和相对目标目录。Vault 必须包含 `.obsidian` 目录。
3. 刷新后生成总览及按月全部采样表；以后成功写入读数后自动更新。

只覆盖含本工具生成标记的文件，目标必须位于配置的 Vault 内。Markdown 为只读派生查看稿，SQLite 是原始数据。同一目标只指定一个设备生成，避免同步冲突。关闭导出可移走本机导出配置；历史 Markdown 不会被删除。

## 公告来源

公告来自第三方 [Codex Resets](https://codex-resets.com/) 的[公开 API](https://codex-resets.com/api/docs)。预告窗口只是站点对推文的解读，不是确定的账号重置安排；实际账号状态仍以额度接口为准。
